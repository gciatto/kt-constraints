# M1 — Exact finite-domain modelling foundation

Implemented on `develop`, using JVM-only TDD iterations followed by milestone-wide checks.
Test commits are separate from implementation commits. The local implementation plan is not tracked.

## Delivered

- Exact kt-math 2.1.2 integer literals, finite-domain bounds and integer assignment values. Int/Long factories
  remain convenient inputs; oversized integers are never narrowed implicitly.
- Canonical immutable finite domains: intervals, empty/sparse sets, union, intersection and exact cardinality.
- Typed integer arithmetic/order and Boolean operations, structural equality, ordered expression folds and
  exact ground evaluation. Unknown extension nodes and non-ground evaluation fail explicitly.
- Preserved all-different, zero-based element, allowed-tuple table, weighted sum and Boolean cardinality nodes.
- Detached model snapshots, named assertions, annotations, source locations, explicit satisfaction reset,
  output projection, ownership checks and validation of expression sorts.
- Unpublished reusable Kotest contracts with fixed seeds, a compiled Java core consumer, and common Kotlin
  DSL examples executed on JVM and JS.
- One top-level type per source file throughout the touched production modules. Nested sealed variants
  retain their existing qualified names. Kotlin operator groups are split by arithmetic, equality and order.

## Boundaries and next milestone

The numeric API is intentionally changed from the bootstrap: literal values and integer assignment results
are `BigInteger`; domain bounds are nullable `BigInteger` because empty domains have no bounds. Consumers
must migrate bounded conversions to checked conversions. No stable Java/TypeScript facade is claimed.

No solver is operational, no publication is enabled, and no benchmark result is claimed. Infinite domains,
real/rational expressions, division/modulo, scheduling globals and solver-specific lowering remain future work.
Custom expression/domain implementations must honor their immutability contracts.

Serialization has a documented identity/remapping design, not an implementation or round-trip claim.
M2 next defines result/termination/stream and backend-support contracts, a capped test-only finite oracle,
shared solver conformance tests, and the first real MiniZinc vertical slice.
