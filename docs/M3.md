# M3 — MiniZinc engine catalogue

## Delivered CLI slice

Explicit engine selection now reaches discovery, startup probes, checked lowering,
process arguments and result identity. Gecode's entry point remains source-compatible.
Gecode, Chuffed, CP-SAT, HiGHS and CBC share compiler/protocol validation and the same
capability-specific solver contracts. Every returned full assignment is evaluated before
projection. The shared globals/optimization/projection case compares against the finite
oracle. Additional tests exercise broken configurations, missing executables, exact
signed boundaries and the MIP witness-only completion protocol.

MIP enumeration is explicitly unsupported; its two enumeration contracts are disabled
for each MIP engine. MIP arithmetic is restricted to bounded affine integers and requests
zero objective gaps. Proof statuses rely on numerical MIP evidence; no rational certificate
is claimed. See [design and numeric policies](M3-DESIGN.md).

The CI job now installs the official checksum-pinned Linux MiniZinc 2.10.1 bundle and
requires all five engines, rather than silently skipping missing requested runtimes.
Release/publication gates and published module lists remain unchanged.

## JS execution

The official pinned npm package 4.5.2 supplies Chuffed in browser Wasm. Node uses an
installed Gecode CLI. Actual shared solver contracts run on both, including projection,
optimization, globals/oracle comparison, cancellation, owned deadlines, backend close
and runtime reload. Route IDs distinguish `chuffed/minizinc-wasm` from
`gecode/minizinc-js-cli`; neither is claimed as Kotlin/Wasm or WASI.

A backend owns the upstream global pool; only one owner is allowed. Solvers own streams
but leave the backend pool available. Integer assignments remain lossless strings; JS
statistics have upstream Number semantics. The upstream event API lacks backpressure, so
large enumerations can buffer output. No browser validation is inferred from compilation.

### Node SDK lifecycle review (minizinc 4.5.2, Linux, MiniZinc 2.10.1)

Experiments against the pinned SDK established:

- `cancel()` sends SIGINT; given ~200 ms, the CLI and `fzn-gecode` exit and remove all
  temporary files.
- `shutdown()` SIGKILLs only the tracked `minizinc` driver. On Linux, `fzn-gecode` did not
  survive its parent in either the kill-only or SIGINT-then-kill case; macOS was not re-tested.
- SIGINT immediately followed by `shutdown()` (the original backend close path) leaked the
  driver's `mznfile*.fzn` files. Backend close now waits for cancelled runs to exit (bounded
  by five seconds) before shutdown; a Node contract with an isolated `TMPDIR` verifies that
  no files remain.
- A cancel issued before the CLI spawns emits `exit` with code 0 and skips the SDK's own
  `fs.rm` of its run directory. Listeners are detached before cancelling, so this cannot be
  mistaken for completion, but the small `mzn*` directory leaks. This is an upstream defect
  with no safe local workaround; it is documented rather than hidden.
- With a missing executable, `solvers()` rejects and then parses empty stdout, throwing an
  uncaught `SyntaxError` that terminated the Node process. Loading now probes `version()`
  first and reports `BackendUnavailableException`; a Node contract covers this.

Kotest JS executes specs inside one Mocha anchor test (`Kotest.Executor`) and replays recorded
results as Mocha suites afterwards. A throwing `beforeSpec` therefore left an empty suite, so the
spec now reports load failures from each test with the cause attached.

### Resolved: intermittent browser report loss

The browser job failed intermittently with "The requested MiniZinc JS runtime contract did not
execute": the report held only the passing `Kotest.Executor` anchor. Reproduced locally with
Playwright Chromium pinned to two CPUs (Google Chrome is denied sockets on the validation host),
instrumentation showed the cause. The upstream browser pool spawns a replacement worker for every
run; backend close (and cancellation) could terminate it during `importScripts`. Chrome reports
that as an uncaught page `NetworkError`; Mocha attributes it to the already-passed anchor and
aborts the run, so every replayed spec suite is skipped. This affected users' pages too.

The browser route now keeps one pooled worker and awaits `version()` — which reuses the pooled
worker instead of replacing it — before each run start and before shutdown, so only loaded
workers are terminated. Run starts are serialized with that step. Karma delays the worker
script by 300 ms so the race is deterministic: the new browser contract failed 3/3 before the
fix and the suite passed 8/8 after it (4 runs pinned to two CPUs, where about 60% failed before).
The report gate was not changed. Karma also writes all browser console output to
`browser-console.log`, uploaded by CI on failure.

## Remaining boundaries

No FlatZinc parser is needed by this route, so the placeholder format module remains
unpublished. MiniZinc owns flattening and global decomposition. Browser Wasm requires the official
worker/Wasm/data assets to be served; the repository's Karma setup does this in CI and
local Chrome tests. Direct engines, Native command transports and stable Java/TypeScript
facades remain future work. The backend remains unpublished.
