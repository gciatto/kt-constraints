# :interop-c

A C shared library and header, generated by Kotlin/Native for `linuxX64`, `macosArm64` and `mingwX64`. Each GitHub
release attaches it as `kt-constraints-c-<version>-<target>.zip`; `./gradlew :interop-c:releaseAssets` builds the
zips this host can link into `build/distributions`. It is not a Maven publication: Kotlin/Native users depend on the
other modules' klibs instead.

- **Modelling:** `ModelBuilder` with `intVar(name, min, max)`, `boolVar(name)` and `realVar(name)`; `IntExpression` (`plus`, `minus`,
  `times`, `negate`, `eq`, `neq`, `lt`, `le`, `gt`, `ge`) and `BoolExpression` (`and_`, `or_`, `not_`, `implies`,
  `iff`); `constant(long)`, and `constantOf("…")` for exact integers of any size; `allDifferent` and `sum` over an
  `IntExpressionList`; `RealExpression` with exact arithmetic and comparisons, `realConstant("4.5")` /
  `realConstant("9/2")`, and `IntExpression.toReal()`; `minimize` / `maximize` and `minimizeReal` / `maximizeReal`;
  `build()` returns an immutable `Model`.
- **Solving:** `solve(model, timeoutMillis)` blocks the calling thread and uses the solvers bundled for Kotlin/Native,
  including the pure-Kotlin exact solver and Z3 through its C API. Z3 is loaded at run time from
  `KT_CONSTRAINTS_Z3_LIBRARY` or the loader path. The `Outcome` gives `status` (`OPTIMAL`, `FEASIBLE`, `INFEASIBLE`, … or `ERROR` with a `message`), the
  answering `route`, the exact integer `objective` or rational `realObjective`, and `valueOf` / `valueOfReal` /
  `truthOf` for variables.
- **Exactness:** integer values come back as decimal strings and real values as exact rational strings, so nothing is
  truncated to 64 bits or rounded to floating point.
- **No exceptions cross into C** (they would abort the process): invalid input gives a null handle or `false`, and
  solver failures give an `ERROR` outcome.

Kotlin/Native's conventions apply: every object is a handle to free with `DisposeStablePointer`, every returned
string is freed with `DisposeString`, and names that clash with C keywords get a trailing underscore.

```c
#include <stdio.h>
#include "libktconstraints_api.h"

#define KC (lib->kotlin.root.io.github.gciatto.ktconstraints.c)

int main(void) {
    libktconstraints_ExportedSymbols *lib = libktconstraints_symbols();

    libktconstraints_kref_io_github_gciatto_ktconstraints_c_ModelBuilder builder = KC.ModelBuilder.ModelBuilder();
    libktconstraints_kref_io_github_gciatto_ktconstraints_c_IntExpression x = KC.ModelBuilder.intVar(builder, "x", 1, 9);
    libktconstraints_kref_io_github_gciatto_ktconstraints_c_IntExpression y = KC.ModelBuilder.intVar(builder, "y", 1, 9);
    KC.ModelBuilder.add(builder, KC.IntExpression.gt(x, y));
    KC.ModelBuilder.maximize(builder, KC.IntExpression.times(x, y));

    libktconstraints_kref_io_github_gciatto_ktconstraints_c_Outcome outcome = KC.solve(KC.ModelBuilder.build(builder), 0);
    const char *status = KC.Outcome.get_status(outcome);  // "OPTIMAL"
    const char *vx = KC.Outcome.valueOf(outcome, x);       // "9"
    printf("%s: x = %s\n", status, vx);
    lib->DisposeString(vx);
    lib->DisposeString(status);
    lib->DisposeStablePointer(outcome.pinned);
    lib->DisposeStablePointer(builder.pinned);
    return 0;
}
```

`src/nativeUsageTest/c/usage.c` is the executable reference. `./gradlew :interop-c:nativeUsageTest` compiles it with
the host's `cc` against the host's library and runs it against the pinned Z3 build. It is part of `check`, and of
CI's `test-native` job on Linux and macOS.
